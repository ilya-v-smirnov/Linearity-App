```
linearityapp/                    # R-пакет
├── DESCRIPTION, NAMESPACE, NEWS.md, LICENSE, CITATION.cff
├── R/
│   ├── io_read.R          # чтение: plate-формат, long-формат, legacy

│   ├── qc_metrics.R       # CV, recovery, bias, приёмка стандартов/QC
│   ├── limits.R           # LoB / LoD / LoQ, LLOQ / ULOQ
│   ├── flags.R            # правила флагов
│   ├── analysis.R         # run_analysis(data, params) → объект "lin_analysis"
│   ├── report.R           # render_report() (Quarto/R Markdown)
│   └── app_*.R            # Shiny-модули
├── inst/app/              # run_app()
├── inst/report/report.qmd
├── inst/extdata/          # примеры данных
├── tests/testthat/
├── vignettes/
└── .github/workflows/     # R-CMD-check, test-coverage, pkgdown
```

Ключевой принцип: **вся статистика — чистые функции без Shiny**, тестируемые отдельно. Приложение только собирает параметры и вызывает `run_analysis()`. Тот же анализ воспроизводим из консоли:

```r
x <- read_assay("plate.xlsx")
res <- run_analysis(x, params = analysis_params(model = "4PL", weights = "1/y^2"))
render_report(res, "report.html")
```

> Отклонения от плана: шаблон-таблица по-прежнему создаётся в старом шестистолбцовом виде; QC-лист в шаблоне пустой (заполняется пользователем); схема-шаблон ставит каждую серию стандарта в отдельный столбец.

Проблемы текущего формата: шесть обязательных столбцов, повтор концентраций стандартов в каждой реплике, пустые `NA`-ячейки, нет идентификатора лунки/реплики/планшета, нет типов blank и QC.

**Основной формат — «планшет» (Excel-книга из шаблона):**

| Лист | Содержимое |
|------|-----------|
| `OD` | Сетка 8×12 (или 16×24) — вставляется прямо из экспорта ридера |
| `Layout` | Та же сетка с кодами лунок: `S1…Sn` — стандарты, `B` — бланк, `NC`, `QC-L/M/H`, `X1…Xn` — образцы, пусто — не используется |
| `Standards` | `level`, `conc` (или старт + шаг — заполняется автоматически) |
| `Samples` | `id` (X1…), `name`, `dilution`, произвольные метаданные (дата, группа…) |
| `QC` | `id`, номинальная концентрация |

Реплики определяются автоматически по одинаковым кодам в `Layout`. Одна сессия = один планшет (Q5); формат 96 и 384 лунок. Шаблон и подписи листов — на выбранном языке, но коды лунок (`S`, `B`, `QC`, `X`) не зависят от языка.

**Альтернативный формат — «длинная таблица»** с минимумом обязательных столбцов: `type`, `id`, `OD`; `conc` нужен только для стандартов/QC, `dilution` по умолчанию = 1.

**Обратная совместимость:** старый формат распознаётся автоматически и конвертируется.

Валидация возвращает полный список проблем (не первую ошибку) с указанием лунки/строки; показывается в UI таблицей.

> Отклонения от плана: критерии по умолчанию взяты из ICH M10 для лиганд-связывающих методов (±20 %, ±25 % на краях, CV ≤ 20/25 %), а не 15/20 % из таблицы ниже (они остаются доступны в редакторе); определение НПКО/ВПКО по принятым уровням стандарта перенесено сюда из этапа 5A; линейность разведений оценивается относительно среднего по всем разведениям образца; флаг «extrapolated» не нужен — экстраполяция не выполняется; не прошедшие критерии внутренние уровни стандарта не исключаются автоматически (пользователь может исключить их на вкладке кривой). Критерии пока не сохраняются между сессиями — это этап 6 (профиль метода).

Для каждого запуска:

| Показатель | Как считается | Критерий по умолчанию (настраивается) |
|-----------|----------------|------------------|
| CV реплик (OD и конц.) | SD / mean · 100 % | ≤ 15 % (≤ 20 % у LLOQ) |
| Recovery стандартов (back-calculation) | рассчитанная / номинальная · 100 % | 85–115 % (80–120 % у LLOQ/ULOQ) |
| Приёмка калибровки | доля стандартов, прошедших критерий | ≥ 75 % уровней, включая крайние |
| Bias / recovery QC | (среднее − номинал) / номинал | ±15 % (±20 % у LLOQ) |
| Качество кривой | R², SE остатков, сходимость, CI параметров, тренд остатков | предупреждение при выходе |
| Линейность разведений | recovery конц. образца между соседними разведениями; CV по разведениям | ±20 %; флаг «нелинейное разведение / matrix effect» |
| Precision внутри планшета | CV реплик QC/образцов | ≤ 15 % |
| Precision между запусками | ANOVA-компоненты: repeatability, intermediate precision (CLSI EP05 / ISO 5725) | только в режиме валидационного исследования (этап 5B) |

Флаги на уровне образца: `< LoD`, `< LLOQ`, `> ULOQ`, `extrapolated`, `high CV`, `dilution non-linear`, `excluded`. Каждый флаг виден в таблице, отчёте и экспортах. Критерии хранятся в **профиле метода** (см. этап 6) — значения по умолчанию ориентированы на ICH M10 / FDA BMV, пользователь может менять.

### Этап 5. LoB, LoD, LoQ (v0.6.0) — ~1–2 недели

Два режима, т.к. корректная оценка требует данных за несколько запусков:

**A. Оценка в рамках одного запуска (ориентировочная)**
- LoB = mean(blank) + 1,645 · SD(blank) (параметрическая) или 95-й перцентиль (непараметрическая).
- LoD = LoB + 1,645 · SD(низкий образец) — при наличии низкоуровневых реплик; иначе — альтернативный подход mean(blank) + 3 · SD(blank), пересчитанный в концентрацию через кривую.
- LLOQ/ULOQ = крайние стандарты, прошедшие критерии recovery и CV.
- Precision profile: CV рассчитанной концентрации vs концентрация по CI обратного предсказания; LoQ = минимальная концентрация, где CV ≤ целевого (20 %).

**B. Валидационное исследование (CLSI EP17-A2)** — несколько запусков/дней/лотов. Поскольку в сессии обрабатывается один планшет (Q5), данные исследования собираются из сохранённых файлов анализа отдельных запусков (этап 6): отдельная вкладка «Валидация» загружает N файлов анализа и объединяет бланки, низкие образцы и QC.
- LoB по ≥ 60 измерениям бланков (с учётом поправки на число серий);
- LoD с поправочным коэффициентом `cp = 1,645 / (1 − 1/(4(N − K)))`;
- LoQ — наименьшая концентрация, удовлетворяющая цели по общей ошибке (TE) или CV.
- Результат сохраняется в профиль метода как **валидированный диапазон** и используется для флагов в рутинных запусках.

### Этап 6. Отчёт и воспроизводимость (v0.7.0) — ~2 недели

Отчёт из шаблона Quarto/R Markdown → HTML, PDF, DOCX, на русском или английском (Q6; язык отчёта выбирается независимо от языка интерфейса). Разделы:

1. **Шапка**: название эксперимента, оператор, дата анализа, ID запуска, имя входного файла + SHA-256, версия приложения/R/пакетов.
2. **Параметры анализа** (зафиксированные): модель, взвешивание, вычитание фона, критерии приёмки, профиль метода и его версия, правила округления.
3. **Калибровка**: график с CI, параметры с CI, таблица back-calculation (номинал, рассчитано, recovery, CV, принят/отклонён), остатки, статус приёмки.
4. **Показатели качества**: QC-таблица, LoB/LoD/LoQ, LLOQ/ULOQ, precision.
5. **Результаты образцов**: среднее, SD, CV, n, конц. с учётом разведения, флаги.
6. **Исключения**: какие точки исключены, кем, когда, по какой причине.
7. **Предупреждения**: все сработавшие правила.
8. **Приложение**: sessionInfo, полный журнал.

Плюс:
- **Файл анализа** (`.json`/`.yaml`) — параметры + исключения; загрузка воспроизводит анализ один в один.
- **Профиль метода** (`.yaml`) — для конкретного assay: единицы, модель, веса, критерии, валидированный диапазон. Выбирается при загрузке данных.
- Экспорт результатов в Excel (несколько листов: результаты, калибровка, QC, флаги, параметры).

**Опциональный режим GLP (Q4)** — выключен по умолчанию, включается в профиле метода или настройках:
- обязательные поля оператора и причины для любого исключения/изменения параметров;
- журнал действий с временными метками внутри файла анализа;
- отчёт с SHA-256 входных данных и самого отчёта, PDF без возможности редактирования;
- блокировка параметров профиля метода (изменение → новая версия профиля).
Полноценные электронные подписи и учёт пользователей — в бэклоге (требуют серверного развёртывания с аутентификацией).

### Этап 7. Профессиональный репозиторий (v1.0.0) — параллельно, финализация ~1 неделя

- README: бейджи (R-CMD-check, coverage, lifecycle, лицензия), скриншоты/GIF, установка одной командой `remotes::install_github(...)`, быстрый старт.
- Сайт документации `pkgdown` (GitHub Pages): справка по функциям, виньетки «Быстрый старт», «Формат данных», «Методы расчёта и формулы» (с источниками), «Валидация LoD/LoQ».
- Руководство пользователя — из `.docx` в Quarto (версионируемый текст, а не бинарник).
- NEWS.md, семантическое версионирование, GitHub Releases, Zenodo DOI, `CITATION.cff`.
- CONTRIBUTING.md, CODE_OF_CONDUCT.md, шаблоны issue/PR.
- Два способа использования (Q3): установка пакета `remotes::install_github(...)` + `run_app()`; веб — Docker-образ (для сервера лаборатории) и публичное демо на shinyapps.io / Posit Connect с примерами данных.
- README, руководство пользователя и сайт — на английском с русской версией (`README.ru.md`, переключатель языка на pkgdown-сайте).
- Верификационный отчёт: сравнение результатов 4PL/5PL и LoD с эталонными реализациями/опубликованными примерами (важно для доверия в лабораториях).
